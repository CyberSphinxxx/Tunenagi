# Kotlin / Android Architecture Contract

## Guiding constraints

One application process with a long-lived `MediaLibraryService` owning the sole Media3 Player. Compose UI observes StateFlow snapshots, sends commands via controller/domain use cases; it **never owns its own player instance**. Domain code uses interfaces without depending on Android views/network DTOs. Provider adapters map foreign data into stable internal models. Persist a source-neutral local library independent from remote identifiers.

## Build organization (logical; split Gradle modules only when justified)

```
app/                    # Activity, Hilt graph, navigation, app startup
core/model/             # Track, TrackSource, queue, Error, ProviderKey
core/database/          # Room entities/DAO/migrations
core/playback/          # MediaLibraryService, session callback, queue coordinator
core/library/           # repo interfaces, source matching, import/export
core/network/           # HTTP, cache, result wrappers, rate limiting
core/plugins/           # external manifest schema, validator, executor
core/designsystem/      # tokens, components, themes
feature/home search library player playlists lyrics pluginmanager settings/
provider/local audius musicbrainz/
integration/lrclib/
plugin-sdk/ sample-plugins/ benchmark/ docs/
```

Start minimal `:app` + `:core:model` + `:core:database` + `:core:playback` + `:core:plugins`; other modules may be packages at first. **Avoid dozens of empty modules.** Use version catalog and dependency locking; pin AGP/Kotlin/Compose/Media3 versions after checking release compatibility. JDK version must match AGP. Never put secrets in `BuildConfig` (extractable).

## Dependency direction

UI -> domain interfaces/use cases -> repositories -> providers/database/network. Playback coordinates `TrackSource` -> fresh `PlayableReference` -> MediaItem using provider resolvers. Plugins must not see `Room`, Android `Context`, host tokens, MediaStore or raw HTTP clients. Network permission checks happen in host network gateway; no plugin-issued bare `OkHttpClient`.

## Repository interfaces (illustrative)

```kotlin
interface CatalogProvider {
  val id: ProviderId
  suspend fun search(query: SearchQuery, page: PageKey?): Page<ExternalTrack>
  suspend fun getTrack(externalId: String): ExternalTrack?
}
interface PlaybackSourceResolver {
  val providerId: ProviderId
  suspend fun resolve(track: Track, source: TrackSource): ResolveResult
}
interface LocalLibraryRepository { fun tracks(query: String?): Flow<PagingData<Track>> }
interface PlaylistRepository { fun entries(id: PlaylistId): Flow<List<PlaylistEntry>> }
```

Change signatures as necessary, but keep separation and error taxonomy. TrackId is a UUID generated by Tunenagi, NOT Audius or MBID. Remote URI often expires; don't store it as canonical media identity.

## App state and lifecycle

Use ViewModels with immutable UiState sealed states (`Loading`, `Content`, `Empty`, `Error`) and one-off effect channel where appropriate. Navigation graph is independent of player service lifecycle. Queue and current position debounce persistence; immediate save on pause/stop/queue edit and routine progress checkpoints. Model app restart and process reclaim without assuming service survives a user force-stop.

## Storage and sync

Room for normalized relational data with foreign keys/indexes/transactions and explicit migration tests. DataStore for small preferences; no metadata in giant JSON blobs. Content URI access: MediaStore may require permission; SAF use persistable permissions when granted. Verify source exists before playback. WorkManager for deferred rescans/cleanup only, not foreground audio.

## Network

HTTP client with timeouts, bounded response bodies, cancellation, structured error model, provider-specific rate limiting, cached metadata where permitted, exponential backoff with jitter honoring Retry-After. Do not retry permanent 401/403 as if transient. No indefinite loading state. Sanitize sensitive logs and track URLs.

## Performance

Cold start shouldn't synchronously scan or fetch network. LazyColumn paging/images loaded async; incremental catalog scans; image downsample/caches; strict dispatcher usage; bounded caches. Measure with Macrobenchmark on release variant/representative device. Avoid unbounded prefetch or uncompressed PCM caching.

## ADR policy

If architecture deviations needed, log `STATE/decisions.md` entry: ID, context, options, chosen, consequences, dependent tasks, tests. No silent global refactor. Any materially changed entity/schema requires migration and upgrade test.
