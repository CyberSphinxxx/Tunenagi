| Trap (from `PHASES/01-domain-and-persistent-storage.md`) | How it was actually checked | Result |
|---|---|---|
| Provider ID used as a primary key | Audit read the exported schema and listed every table's primary key: `tracks/albums/artists/playlists/playlist_entries/track_sources/playback_*` are all `id`; `track_artists` is the composite credit tuple; `lyrics_cache` is `(trackId, provider)`; `favorites`/`metadata_matches` are `trackId`. No `externalId`, `providerId`, `mbid`, `isrc` or URI appears in any primary key. `TrackId`/`ProviderId` are distinct types, so a provider id cannot even be passed where an app id is expected. | PASS |
| Accidental deletion after source loss | **Not covered** — this audit's finding. BUG-0002 filed (Low) and closed: `DatabaseConstraintTest.deletingASourceLeavesTheTrackCreditsAndPlaylistsIntact` now deletes the `track_sources` row and requires the track, credit, playlist entry and favourite to survive. | PASS after fix |

## Threats / API rights / privacy / accessibility checks

- `secret_scan.py --history` exits 0 over every commit; no credential, token or key is in the tree.
- No provider is contacted anywhere in phase 01: there is no HTTP client code yet, and
  `check_ci.py` (C5) keeps provider hosts out of CI.
- The database stores no stream URL as identity: sources are `(providerId, externalId, variant)` and
  `PlayableReference` carries its own expiry instead of being persisted as a track's identity.
- Plugin rows store the domains the user approved (`approvedDomainJson`) rather than trusting a
  manifest, and B5 already forbids `core.plugins` from importing Room, Context or a raw HTTP client
  before any plugin code exists.
- Accessibility is untouched in this phase (no UI changed); the phase-07 audit owns it.
