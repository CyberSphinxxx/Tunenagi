## Threats / API rights / privacy / accessibility checks

- No storage permission was added: the only read path is the grant the user picks through the system
  picker, persisted with `takePersistableUriPermission`. No MediaStore permission is requested, and
  the device-wide scan is not wired (phase 04 owns the consent story).
- The merged manifest still declares only `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`,
  `POST_NOTIFICATIONS` and `WAKE_LOCK`; `PlaybackManifestTest` asserts that recording, contacts and
  camera permissions are absent.
- Nothing is uploaded. Diagnostics remain a bounded in-memory window of resolve attempts with no
  uri, file name or title.
- The import path stores tracks, not paths as identity: a queue item is a track id and a source, and a
  failed resolve is a typed state rather than a deleted row (BUG-0002's rule).
- Accessibility: the new control has a text label and the mini-player's controls keep action-named
  content descriptions; the import state is text, not colour alone. No visual/contrast work was
  needed, but no screen reader has ever announced any of it (deferred).
- No provider terms or scraping are involved in phase 02: the only source is a file the user pointed
  at.

## Regression impact on prior phases

- Phase 00 and 01 evidence is untouched; schema, migrations and boundaries are unchanged. The full
  329-test suite includes the migration suite, boundary self-test and the shared Compose suite.
- `verify.py` remains the single entry point and still runs 9 steps; the new tests are picked up by
  its `unit-tests` step, not by a second pipeline.
- `PlaybackQueueCommands.apply` now also sets repeat mode. That is a behaviour change for every
  caller that applies a queue, and it is what the stored `repeatMode` always implied; existing tests
  that cycle repeat mid-queue still pass.

## Final decision

**PASS** on the machine-verifiable half of phase 02. The phase now has a real user path from a
picked folder to a playing queue, a persisted queue that survives relaunch with its repeat mode, and
bounded retry with an honest failure state. It has **never run on an Android device**: no audible
playback, no airplane mode, no notification/lockscreen, no real `ContentResolver` read, no folder
picker, and no `MediaController` round trip has been observed. `OPERATIONS/DEFERRED_VERIFICATION.md`
lists that missing proof, and the release gates still require it to be closed or explicitly accepted
by the owner.
