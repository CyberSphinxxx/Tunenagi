## 1. Did the implementation actually deliver the contract?

### Search endpoint
- `AudiusApi.search` hits `GET https://api.audius.co/v1/tracks/search` with `query`, `app_name`,
  `limit`, `offset` (`AudiusApiTest.searchUsesTheDocumentedPathAndSendsIdentificationAndPaging`).
- A blank query is refused before any socket is opened (`blank-query`, zero calls recorded).
- `app_name` is sent for every request; a configured read-only key is sent as `x-api-key` only when
  non-blank (`anApiKeyIsSentAsTheDocumentedHeaderOnlyWhenConfigured`). No key is invented, and a blank
  key is treated as absent.

### Trending endpoint
- `AudiusApi.trending` hits `GET https://api.audius.co/v1/tracks/trending` with `app_name`, `limit`,
  `offset` and no search term (`trendingUsesItsOwnPathAndSendsNoSearchTerm`).

### Pagination
- `limit` is bounded to `1..MAX_PAGE_SIZE` and `offset` to `>= 0` at the boundary, before the network
  (`pagingArgumentsAreValidatedAtTheBoundary`).
- The client sends offset-based pagination only, not a cursor. A full page offers `nextOffset`, a short
  or empty page ends paging (`aFullPageOffersTheNextOffsetAndAShortPageEndsPaging`).

### Identity / UA / auth per docs
- `OkHttpTransportTest.aRequestCarriesTheConfiguredIdentityAndEncodedQuery` asserts the `User-Agent`
  header and the exact encoded query parameters, against a real `MockWebServer`.
- The provider adapter never reaches OkHttp/Retrofit directly (rule B11); the HTTP surface is the
  `HttpTransport` gateway. That is not TUN-0301 alone — it was enforced in phase 02 — but it is the
  reason TUN-0301 reuses a real bounded HTTP client rather than building its own.

### What the client deliberately does NOT do
- No undocumented parameter (`time`, `sort`, host-discovery rotation), no non-HTTPS base URL
  (`aBaseUrlThatIsNotHttpsIsRefused`), no invented key.
- The docs shape is recorded in `AudiusApi`'s class doc with the dates and URLs checked (2026-10-20),
  and in ADR-017.

## 2. Are the contract tests actually recording the contract, or just asserting against a fake?

Two complementary test layers exist, and each covers a different failure surface:

- `OkHttpTransportTest` drives a real `MockWebServer` over a real loopback HTTP socket and asserts the
  request identity, body budget, `Retry-After` parsing, timeouts, and the redirect policy. This is the
  surface a recording fake cannot check.
- `AudiusApiTest` uses a recording fake transport so the *request* can be asserted exactly (path, query,
  headers, number of calls), and so the parsing/entitlement/pagination failures can be driven without a
  network. This is the surface `MockWebServer` makes awkward to drive (you would have to craft exact
  bodies for every malformed case).

Neither layer is live. `AudiusApiTest`'s class doc states the fixtures are written from the documented
shape and explicitly not captured live. That is the correct posture given ADR-008 and the CI rule that
provider traffic is forbidden.

## 3. Negative / failure paths covered

Provider taxonomy:
- `httpFailuresUseTheDocumentedTaxonomy` maps 401→Unauthorized, 403→Restricted, 404→NotFound,
  429→Throttled(9s), 500→Timeout, and passes a transport failure through unchanged.
- `aPayloadWithoutTheDocumentedEnvelopeIsMalformed` treats `{}`, `{"data":null}`, malformed JSON and a
  bare `{` as `MalformedPayload`, not "no results".

HTTP behaviour (real server):
- body budget exceeded → `MalformedPayload` (`aBodyLargerThanTheBudgetIsRefusedRatherThanBuffered`);
- silent server → `Timeout` (`aSilentServerBecomesATimeoutNotAGenericFailure`);
- closed server → `NetworkUnavailable` (`aClosedServerBecomesNetworkUnavailable`);
- `Retry-After` seconds and HTTP-date both parsed (`aRetryAfterInSecondsIsParsed`,
  `aRetryAfterAsAnHttpDateIsParsedToo`);
- redirect to allowed host followed, to non-allowed host refused, plain-HTTP redirect refused even when
  the host is allowed, and redirect budget bounded (`aREDIRECT_TESTS` group).

Request validation:
- blank query refused before the network;
- `limit`/`offset` out of range throw `IllegalArgumentException` before the network;
- non-HTTPS base URL refused at construction.

That is more than one negative path; it spans request validation, HTTP behaviour and provider error
mapping.
