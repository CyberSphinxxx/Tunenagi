## 1. The contract came from the provider's own document

The slice is built on `https://api.audius.co/v1/swagger.yaml`, fetched on 2026-10-21, not on an older
example:

- `GET /tracks/{track_id}/stream`, server root `/v1`;
- `no_redirect: "If true will not return a 302 and instead will return the stream url in JSON"`;
- `200 → application/json → stream_url_response`, whose only property is `data: string`;
- `security: [{}, {OAuth2: [read]}]`, so the empty requirement permits an unauthenticated read of a
  public track.

`ADR-018` records the decision to use the JSON form and the consequences.

## 2. Late resolution, and why nothing can go stale

- `resolve(track, source)` performs the request at the moment the player needs an item; there is no
  cache, no field on `TrackSource` holding a URL, and no code path that returns an earlier result.
  A media id names a *source*; the URL is produced from it again on the next playback.
- The returned `PlayableReference.expiresAt = clock() + STREAM_REFERENCE_LIFETIME` (10 minutes) is
  labelled in code and in ADR-018 as this app's re-resolution budget. The provider documents no
  lifetime, so claiming one would be the invention; claiming the URL is indefinitely fresh would be
  the opposite error. The test asserts both sides of `isExpiredAt`.
- `mimeType` is null because the bytes are never fetched; Media3 sniffs the stream instead of being
  told a format the app cannot substantiate.

## 3. No bypass

- A source whose availability is `Restricted` (TUN-0302's encoding of the provider's own refusal) is
  answered with `ProviderError.Restricted` **without a socket being opened**; the test asserts zero
  requests.
- The query is exactly `app_name` and `no_redirect=true`; the test asserts the full parameter-name
  set, so a future signature, access token, `preview` or `skip_play_count` cannot be added silently.
- A `302` is not followed to whatever host it names: the transport refuses it (`allowedRedirectHosts`
  is empty for this client) and the test asserts exactly one request even though a second response is
  queued to make a following resolver "succeed".
- A returned URL must be HTTPS with a real authority. Plain HTTP is accepted only for loopback under
  the test flag; `javascript:`, `http://content.example/...` under production policy and a
  userinfo URL (`https://127.0.0.1@evil.example/...`) are all refused with
  `ProviderError.Unknown("stream-url-rejected")` and are not echoed in the error.
- A provider id that could escape its path segment (`../me`) is `MalformedPayload` and sends nothing.

## 4. Failure taxonomy

| Provider answer | Result | Test |
|---|---|---|
| `404` | `ProviderError.NotFound` | `a404IsNotFoundNotAGenericFailure` |
| `401` | `ProviderError.Unauthorized` | `a401IsReportedAsUnauthorized` |
| `403` | `ProviderError.Restricted()` | `a403IsReportedAsRestricted` |
| `429` + `Retry-After: 9` | `Throttled(9s)`, retryable | `a429KeepsItsRetryAfterInsteadOfBecomingPermanent` |
| `200` with `data: null`, blank data, or non-JSON | `MalformedPayload` | `aBodyWithoutADataUrlIsAMalformedPayload` |
| a source from another provider | `Unknown("not-an-audius-source")`, no request | `aSourceFromAnotherProviderIsRefusedWithoutANetworkCall` |

Bounded retry is deliberately **not** here: TUN-0304 owns it, and mixing a retry loop into the
resolver would pre-empt that task's policy.

## 5. Tests and evidence

- `AudiusStreamResolverTest`: 12 tests, 0 failures, 0 errors, 0 skipped
  (`core/build/test-results/testDebugUnitTest/TEST-...AudiusStreamResolverTest.xml`). Eleven run
  against a real `MockWebServer` through the production `OkHttpTransport`, so the request line, the
  identifying header, the redirect refusal and `Retry-After` are real HTTP behaviour rather than a
  fake's agreement. The two production-policy tests use a recording transport because the production
  base URL must stay HTTPS, which a loopback server cannot serve.
- Targeted run, exit 0 (`--rerun`, so the task really executed):
  `STATE/evidence/TUN-0303/20261020T223552Z-audius-stream-resolver-tests.json`.
- Full pipeline, exit 0, `VERDICT: PASS - 9 step(s) green`, with unit tests (43.6s), assemble and
  lint (85.7s) actually running:
  `STATE/evidence/TUN-0303/20261020T223637Z-verify-all-steps.json`.
- An earlier run of the same targeted test failed
  (`20261020T223452Z-...`) because `https://127.0.0.1@evil.example/...` was accepted: the scheme was
  checked but not the authority. The fix requires a parsed host even for HTTPS, and the security test
  that caught it is the one now passing. The failing manifest was kept rather than deleted.

## 6. Limitations (not hidden)

- **No live Audius request.** No credential exists (ADR-017), CI must not call the provider, and the
  fixtures are written to the documented schema rather than captured. The live, rate-respecting smoke
  is TUN-0306.
- **No device proof.** ADR-008 defers device runs; this slice has no runtime surface of its own beyond
  the JVM test. `OPERATIONS/DEFERRED_VERIFICATION.md` records the substitute and its limits.
- **Not wired into the app graph yet.** TUN-0305 (remote search/discovery UI) and TUN-0306 own
  installing the resolver and proving an end-to-end play; nothing here claims the app can play a
  remote track today.
- **Gated-but-streamable rows fail late.** The discovery DTOs do not read `is_stream_gated`, so such a
  track is presented as `Available` and only the provider's `401` at resolve stops it. Recorded in
  ADR-018 as a follow-up, not as a bypass.

## 7. Verdict

The slice resolves a public track's stream at playback time, refuses restricted sources before any
request, keeps the provider's error taxonomy, never follows a redirect or invents a format or an
expiry, and proves all of that with a real HTTP server plus a real transport. The full pipeline is
green with the new files in the tree. It does not claim live or device proof, and it does not claim
end-to-end integration, which TUN-0305/TUN-0306 still own.
